# SOP任务内容

当前业务层级固定为项目 → 子项目 → SOP任务。任务直接维护步骤、图片、视觉标注和设备要求；不再提供独立标准创建、选用、更换或发布后绑定流程。

## 使用流程

1. 项目 → 子项目 → SOP任务 → 新建任务，填写名称、工位及负责人。
2. 点击“保存并进入编辑”，或已有任务的“编辑内容／编辑”。系统自动建立任务自己的内容，无需填写另一份名称、编号或关联信息。
3. 在三栏制作页维护步骤，上传PNG/JPEG底图并标注，保存草稿；退出、刷新或下次进入均可继续同一草稿。
4. 点击“发布任务内容”，后台一次完成发布与任务当前内容更新，校验任务版本、权限与工位硬件，任一步失败全部回滚。
5. 任务直接使用三栏制作界面，默认查看，顶部可切换编辑；“返回子项目”返回任务列表，发布后留在当前任务的查看模式。编辑已发布内容时自动创建下一份草稿，原发布快照保留。

工位详情只查询任务并跳转项目任务。修改工位后重新校验设备要求，摄像头角度与检测区域需复核。未保存配置离开前提示，准备编写时先保存配置。只读、归档／完成项目及已取消任务不能编辑。

## 旧数据保留

旧任务已采用的内容继续可查看，第一次编辑时按任务复制步骤、附件和标注，建立独立归属。其他任务及源内容不变，不删除旧标准、关联或版本记录。底层沿用原图文版本能力，界面不再要求用户管理标准对象。

## 部署顺序

已有资源表的数据库先执行一次 [002_task_content.sql](../../../SOP_MySQL/resource-module-v1/migrations/002_task_content.sql)，新增 sop_task_content 归属表，不覆盖任何现有数据。随后重启后台并刷新前端。原建表脚本不要重跑。新建空库的资源 schema.sql 已包含该表，无需额外迁移。实际 MySQL 与硬件联调尚待运行环境验证。

## 接口与目录

POST /project/{pid}/subproject/{sid}/task/{id}/content：校验任务version，自动建立或继续当前任务草稿，返回内部内容ID、草稿ID及最新任务version。重复进入继续同一草稿。

PUT /project/{pid}/subproject/{sid}/task/{id}/publish：发布任务自己的内容，携带 revision_version 和 task_version。旧独立接口保留兼容，正常任务流程不再调用标准选用接口。

任务页位于 src/views/project/task/{index.vue,components,js,styles}，嵌入 src/views/sop/editor 实现查看和编辑；标注、私有图片组件在 src/shared/sop。请求集中在 src/api/resource.js。原内容编辑／发布权限继续保留，普通用户需同时有目标任务和内容编辑权限；root可直接使用。图文图片通过Bearer取Blob，token不放URL。

详细权限及接口见[后台资源说明](../../../SOP_Server_of_Java/docs/resource/README.md)，历史变化见[变更记录](changelog.md)。
