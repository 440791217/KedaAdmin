# 现场摄像头检测接入

## 使用

现场任务要求所属主项目处于“进行中”。项目“未开始”时可以准备、编辑和发布 SOP 内容，但现场任务列表显示不可用原因，开工接口也会拒绝；在项目列表点击“开始项目”后，刷新现场任务即可使用。SOP 已发布与项目已开始是两个独立状态。

1. 启动 Java 业务服务、LocalConverter 和 SOP_Detecter。
2. 系统配置 → 网络配置：保存采集地址 http://localhost:18090 和检测地址 http://localhost:18092；开发凭证均为 88888888，使用明文输入。
3. 测试两个服务连接。检测测试使用带凭证的 /models，显示就绪模型。
4. 现场工作台选择工位与任务，中间图像区域默认显示实时摄像头，开工前即可预览；可点击“查看参考图”切换至步骤参考图，再点击“返回实时画面”恢复。切换到参考图时停止检测和画面绘制，保留任务摄像头连接。
5. 扫码开工或继续现有作业后，实时画面中开始检测。选择该工位的摄像头与检测模型。
6. 当前待确认步骤且作业进行中时自动检测；暂停、查看其他步骤、全部步骤确认后停止检测。完成作业后保留预览，等待下一次扫码；中止作业或退出任务时释放连接。

地址存在浏览器 localStorage，凭证存在 sessionStorage。修改配置后在现场组件点击重新连接。localhost 指浏览器所在电脑；部署时改为实际可访问的服务地址，同时配置两个服务的允许来源。

## 数据流与职责

- Java 返回有权限使用的工位摄像头配置，浏览器交给 Go 创建采集会话；每 10 秒续租，离开任务或页面时释放会话，步骤切换复用任务连接池。
- 浏览器通过 Go 的 WHEP 代理取得 WebRTC 视频。复用现有 CameraSource 的采集生命周期，不调用 Java FFmpeg。
- LiveDetection 将视频截帧为 JPEG，长边最大 960，质量 0.8；调用 Python POST /predict，multipart 中包含 file 和 metadata。
- metadata 包含 model_id、frame_id、station_id、execution_id、step_id。step_id 优先使用发布内容的步骤 ID，无 ID 时使用步骤序号。
- 按配置的检测帧率串行采样，处理超时跳过、不积压；失败等待 2 秒；请求超时 15 秒。不累计待发送帧。浏览器中止请求不代表 GPU 已立即停止，服务可能短暂返回 429，按失败间隔重试。
- 模型列表从 GET /models 读取，仅显示 ready 模型；当前默认模型仍是 COCO 通用类别模型。
- 返回的原图坐标对应上传的缩小帧；绘制时按 object-fit: contain 的比例和留白映射，窗口尺寸变化时重绘。
- 切换步骤、摄像头、模型、暂停、标签页隐藏、断流和销毁时清空检测框、中止请求，使用生命周期编号丢弃晚到结果，并校验返回的全部上下文与图片尺寸。

浏览器将检测结果叠加到持续播放的视频上，框对应最近一次采样帧，会存在短暂延迟。当前步骤全部有效检测区域满足条件后，保存同次采样的现场照片与检测结果并提交步骤确认；保存成功后才推进下一步。

## 固定机位提示框

参考图与实时摄像头默认视角一致，移动摄像头后由人员恢复原位，不做自动配准。实时画面读取当前步骤发布快照中附件的 visual 标注，默认采用第一张带 visual 的附件；多张时可在提示图下拉框选择，不叠加不同附件的区域。

- 操作指引矩形、箭头、文字按归一化坐标映射到视频有效画面，保留标注颜色。
- 启用的检测区域在无结果、等待、暂停及请求失败时仍显示黄色虚线与目标提示；停用区域不显示。
- 支持目标存在与数量条件：类别名称与模型输出名称匹配（例如 cell phone）、达到区域置信度阈值，且目标框中心落在区域内才计入。数量条件使用精确相等。
- 匹配后区域变绿并显示“当前画面条件满足”，表示当前一帧条件成立，不代表步骤通过或已完成持续确认。OCR 和状态类型标记为当前模型不支持，不显示为满足。
- 检测固定读取步骤指定的检测基准图，只画其有效区域匹配到的目标框。缺少检测配置时提示补充，不回退到第一张图片或通用检测。
- 步骤切换时中止原检测、清空原结果并选用步骤绑定摄像头的已有连接。浏览参考图不会改变检测基准。详细制作与部署流程见 [步骤检测配置](step-detection.md)。

SOP 编辑器的目标类别使用可搜索下拉框，通过检测服务 /models 读取就绪模型真实类别，选项标明来源模型；保存 class_name 名称，与现场过滤格式保持一致。旧配置不会自动覆盖，当前模型未提供的旧类别保留显示并提示；连接失败可刷新类别，不提供虚构或任意新增类别。现场需选择支持该类别的模型。标注需保存并发布后生效；已开工的作业继续使用开工时的发布快照，新发布标注需新开工作业验证。

## 代码与验证

## 刷新帧率与检测帧率

公共入口为“系统配置 → 设备配置 → 摄像头”，仅超级管理员可修改，参数保存在后台数据库；默认刷新帧率 0（跟随源流）、检测帧率 2。设备编辑页的 RTSP 摄像头分别选择使用公共参数或单独填写，空值代表继承，可独立恢复继承。修改后重新连接摄像头读取最终配置。

刷新帧率仅控制前端绘制，源帧不足时保持上一画面，不重复绘制；不改变网络接收、解码或摄像头设置。检测帧率为提交上限，串行处理、取最新帧，不积压、不重复提交同一帧。模型耗时过长时实际检测帧率自动降低。两项独立：低刷新帧率不限制检测取最新帧。

LocalConverter 只做 H.264 直通，不再包含 preview_fps 或预览重编码。现有数据库先执行 Server/tools/storage-maintenance.ps1 -Mode apply-frame-rates，再重启 Java 后端；完整数据库初始化及测试 schema 已同步。配置更新接口带版本保护，避免覆盖其他管理员的修改。

实时画面和执行记录共用目标过滤与绘制逻辑：只显示当前步骤启用区域内、类别和置信度符合要求的目标，同一目标不重复画框；没有有效检测区域时不显示通用识别结果。实际目标框沿用区域标注颜色，使用 12px 浅底标签（例如“杯子 86%”）。开工后默认显示检测区域，可取消“显示检测区域”；同一工作台连续作业保留本次选择，未开工不画检测框。执行记录从作业内容快照取标注配置；完整现场原图和原始检测数据仍留存，不因展示过滤而裁剪或删除。

目标类别也支持“从参考图识别推荐”：将当前标注参考图的选定区域实际裁剪出来，四边保留 5% 上下文并限制长边不超过 1280，再调用所选就绪模型；返回坐标以裁剪图为准，排除落在外扩留白内的目标，按置信度排序并合并同名类别，最多显示 5 个候选。用户点击候选后才更新 class_name，不自动替换已保存类别。切换图片、区域或推荐模型会取消旧请求并丢弃迟到结果。此功能只在模型已有类别中推荐，不自动学习新类别，也不能推断操作人员的业务意图。

- src/utils/detection-service.js：独立凭证、网络配置与 multipart 请求，不发送业务登录凭证。
- src/shared/execution/components/LiveDetection.vue、js/live_detection.js：预览、检测循环、坐标映射及生命周期。
- OnsiteWorkbench 在预览指导阶段挂载实时组件，仅预览不调用预测；ExecutionPanel 在现场未结束作业挂载组件并按执行状态启停检测。组件通过 OperationGuide 的 live 插槽进入中间图像区域，历史记录不启动摄像头。
- tests/unit/detection-service.spec.js、components/LiveDetection.spec.js：凭证隔离、串行请求、迟到结果、暂停销毁及画框。
- 构建、测试日志统一在 D:/projects/logs，以 kedaadmin-live-detection 命名。

## 任务摄像头连接池

现场工作台持有 TaskCameraPool，默认最多预连接 4 路任务摄像头。预览、扫码开工、执行、完成后等待下一次扫码共用连接池；同一摄像头沿用同一个已解码 video 元素，不因组件切换重新创建 WebRTC 会话。刷新状态只更新业务数据。独立作业页面使用同一连接池实现，执行记录不拉流。

摄像头按当前步骤、后续步骤、前面步骤的顺序去重预连接；超过 4 路时保留当前显示画面，优先释放备用连接再连接新的目标。只有新源首帧就绪才切换显示。未预连接或断线的摄像头仍需等待首帧，不能保证所有情况零延迟。

所有预连接摄像头持续接收和解码，但只对当前待执行步骤的绑定摄像头提交检测。切步骤、暂停和切参考图均取消旧检测；结果、现场照片同时校验作业、步骤、摄像头、连接代次及新鲜度，迟到结果不用于确认。后台标签页暂停检测，恢复后等待新鲜画面。画面停滞超过 3 秒时单路重连，首次连接等待首帧最多 15 秒；每路最多自动重试 3 次，之后可点重新连接。

刷新帧率 0 使用已有原生播放器；正数只按指定频率绘制最新解码帧，不降低网络接收和后台解码负担。4 路预连接会增加带宽与解码开销，需要按实际摄像头分辨率验证硬件承载能力。LocalConverter 的默认 4 路容量是服务总量，多页面共享；仅回收没有使用者且没有拍照操作的空闲连接，不踢掉其他页面的有效会话。

## 步骤倒计时与完成进度

步骤流程标题右侧集中显示“已完成 N/M”，底部按钮保持原位，不重复显示确认步数。当前执行步骤按发布快照 expected_duration_seconds 显示剩余时间；0 或空值显示实际用时。倒计时临近结束为橙色，超时为红色并继续累计超时时间；条件满足仍立即提交，不等待倒计时归零，也不因超时自动失败。完成步骤显示绿色实际用时。

前端执行页每 5 秒上报实际经过的有效毫秒数，后台把 elapsed_ms 和 remaining_ms 保存到 sop_execution_step_clock。读取时直接返回保存值，不按当前时间减开始时间增长。未启用心跳的旧完成步骤仍可使用历史事件推算展示；旧作业当前未完成步骤从第一次有效执行会话开始累计，不补算过去的离线时间。

## 工位任务卡片入口

可开工且无占用时显示“进入作业”，打开已发布指导等待扫码。该任务有未结束作业时，原操作人显示“继续作业”或“查看暂停作业”，其他账号显示“查看作业”；进入时读取原作业内容快照，保持暂停状态，不自动恢复。未开始、归档、取消、只读账号或被其他任务占用时显示“预览指导”及原因；未发布且没有原作业可查看时显示禁用的“暂无指导”。点击入口重新查询未结束作业，再由作业详情返回的 can_operate/can_abort 限制操作。预览期间只读、占用或状态查询失败时同时禁用扫码输入和开工按钮。

## 到时语音提醒

### 公共语音入口与作业事件

浏览器语音操作集中在 `src/utils/voice-service.js`。执行模块的事件、文案和优先级在 `src/shared/execution/voice-events.js` 定义。新增操作只需增加事件配置，并在业务请求成功且页面响应仍有效后调用 `announceExecution(event, { scopeId, operationId })`。`scopeId` 使用 `execution:<id>`；操作编号使用响应版本号，开工使用请求幂等键。不可在普通详情加载、刷新或查看历史记录时触发。

- 开工：作业开始。
- 暂停／恢复：作业已暂停／作业已恢复。
- 中止：作业已中止。
- 全部步骤确认：步骤已全部完成，请完成作业。
- 完成作业：作业完成，请扫描下一件。

状态语音优先级高于超时语音，超时语音高于步骤说明。状态变化清理同一作业的旧播报，开工提示播放后再播放步骤说明。语音不阻塞接口提交、检测或步骤切换。重复事件按作业、事件和操作编号去重；后续再次暂停属于新的操作，会正常播报。步骤说明和超时提醒仍按作业步骤在同一标签页中去重。

执行页和等待扫码页复用 `JobVoiceControl`。作业语音默认打开，开关保存在当前浏览器；它仅控制作业状态提示，步骤语音继续遵守步骤自身的开关。启动播放失败后显示人工重播入口。自动返回扫码页时保留完成提示，离开工作台时释放所属作业的播放任务。语音失败不回滚业务，也不自动重试业务请求。

工作页在当前步骤取得执行心跳后，自动播报该步骤配置的 `voice_text`。仅正在操作的用户播报，预览、历史、暂停或执行中断时不播报；同一作业步骤在同标签页只自动播报一次，以实际开始播放为准。步骤切换或暂停时停止旧语音。到时提醒优先于操作引导语音，避免两个提示同时排队。调用前恢复浏览器语音引擎；若 5 秒内仍未开始播放，说明区显示错误及人工重播入口。该检查只能发现播放未启动，不能检测电脑静音或扬声器音量。

当前操作人正在执行、步骤启用语音且作业时限大于 0 时，达到时限通过浏览器中文语音播报“步骤……作业时间已到，请注意”。提醒针对真正运行的步骤，浏览其他步骤或参考图不改变判断。每个作业步骤提醒一次，同标签页刷新后也不重复；暂停时不播报，恢复后达到时限再提醒。只读查看、历史记录、已完成或中止、无限时和关闭语音的步骤均不播报。浏览器不支持或拒绝语音时，在右侧说明区显示提示及“重播提醒”，避免静默失败；人工重播由用户点击触发。提醒不自动中止或确认步骤。

## 执行步骤顺序

进行中和暂停作业锁定当前待执行步骤：其他步骤按钮不可点击，不显示手动上一步/下一步。只有当前步骤确认成功后才切换下一步；自动检测需要全部条件满足并保存照片成功，人工步骤需要确认成功。超时、刷新状态和恢复暂停均不跳步。前端事件处理和提交入口分别校验步骤，后端继续校验首个未确认步骤及版本，拒绝乱序确认。全部确认后停留最后一步等待完成作业。未开工指导预览、已结束作业和只读执行记录仍允许逐步查看。

## 前端执行心跳与中断恢复

执行页为当前步骤建立唯一会话，每约 5 秒串行保存有效用时、剩余时间和递增序号；重复序号不重复扣时，步骤版本独立于心跳。超过 15 秒未更新的会话失效，迟到心跳和旧会话确认均被拒绝。数据库时间仅用于判断连接有效期，不用于补扣剩余时间。0 秒步骤只累计用时，remaining_ms 为空；有时限步骤允许剩余值为负以显示超时。

离开执行页面、组件失活、标签页隐藏或 pagehide 时停止心跳，并尽力保存最后不足 5 秒的一段用时及释放会话；通知丢失时依靠 15 秒失效规则。无心跳期间数据库保存值不变；连接正常时前端独立逐秒倒计时，5 秒心跳仅负责持久化。只有保存值或执行状态实际变化时才同步显示起点，相同数据重复传入不重置计时。心跳失败、页面离开或会话中断时停止本地计时，恢复时重新读取保存值。恢复页面不会自动重新启动失活会话，需点击继续作业；从工位卡片点击继续作业属于主动恢复。执行记录和其他人员查看不会建立心跳。

步骤确认、暂停、中止前尽力立即保存本次用时，确认请求带会话标识。确认后旧步骤会话停止，下一步建立新会话；照片上传及确认失败不推进步骤。执行会话独占：其他页面须等原页面释放或超时。

已有数据库执行 Server/tools/storage-maintenance.ps1 -Mode apply-execution-clock 后重启 Java 服务。新增表为增量建表，不修改原作业或照片；新建数据库的 execution-module-v1/schema.sql 与测试 schema 已同步。突然中断通常损失最后未保存的一小段用时，网络异常时不承诺固定误差。

恢复缓存中的旧执行详情时，若缺少 clock_supported，先重新读取后台详情再建立心跳，避免继续使用旧数据导致计时停留在初始值。
## 实际帧率显示

现场开工前预览、执行画面和标注页相机预览在画面左下角显示实测 FPS。直通视频通过浏览器呈现帧回调计数，兼容模式使用播放帧数减去丢帧数；限帧画布仅统计实际绘制的新帧，重复绘制不计数。浏览器无法提供可靠帧统计时显示不可用，不以配置值或屏幕刷新频率代替。FPS 表示前端画面的新帧率，不代表 RTSP 源端发送速率。

检测 FPS 按当前作业、步骤和请求上下文有效的检测完成次数统计。正常返回但没有目标也算一次；失败、取消和过期响应不计入。未开工、暂停、步骤完成分别显示对应状态，不保留旧检测帧率。

设备配置的摄像头页增加画面统计窗口（默认 2 秒，范围 1–30）、检测统计窗口（默认 5 秒，范围 1–60）、数值更新间隔（默认 1 秒，范围 1–5）。数据保存到 `sop_camera_config` 的默认行（`device_id IS NULL`），不放入 SOP 系统参数表。设备覆盖行只保存独立设置的帧率。旧版 `sop_frame_rate_setting` 使用维护工具 `-Mode apply-device-settings` 备份、迁移、核对后删除；不再运行历史帧率迁移命令。该迁移保留原有帧率、版本号与设备覆盖值。

统计参数保存后同页面直接应用，同浏览器其他标签页通过通知重新读取，其他在线客户端最多约 30 秒同步。修改时只重置统计，不重连摄像头、不改变视频或检测帧率；后台断线时保留最后有效配置。初始不足半秒显示统计中，统计窗口内没有新帧时逐步降至 0 FPS。切换摄像头重置统计。静态参考图和历史照片不显示 FPS。
