# 步骤摄像头与检测基准图

当前步骤图片使用单个 image 对象，图片标注提交使用单个 visual 对象。
每个步骤的 detection 配置独立保存：enabled、camera_id、attachment_id、confirmed。
视觉检测关闭时，步骤按操作说明人工确认。开启时必须明确选择当前工位摄像头和本步骤参考图，并确认画面视角与区域位置一致。

## 制作流程

1. 编辑草稿，选择步骤，点击“相机拍照”。编辑页不提供上传图片或图片切换下拉框。
2. 在拍照窗口选择当前工位摄像头、拍照，确认照片后点击“用于当前步骤检测”。
3. 相机与照片在同一后端事务内绑定到步骤，自动开启视觉检测，不再另外选择基准图。
4. 在当前照片上绘制检测区域，填写目标类别、最低置信度、数量等要求，保存后发布。

步骤配置始终显示检测相机与图片状态。重新拍照可选择不同相机；使用新照片前确认替换当前草稿图片及其标注，原发布版本不变。替换失败时保留旧配置。
刷新默认恢复已绑定照片，身份使用附件 ID，不依赖数组顺序。
“移除图片”会同时清除该照片的检测绑定、关闭视觉检测。画布保持空白，不自动选择旧参考图。可以重新拍照。
当前草稿步骤按单图处理：拍照覆盖该步骤全部旧图片引用，移除一次清空全部旧图片引用。已发布历史版本不变。编辑页使用单个 image 和 visual 对象，不维护图片数组；旧 attachments 仅用于读取历史版本的兼容。

## 执行

现场固定读取步骤 detection.attachment_id 的 visual，不能通过参考图浏览改变检测规则。
步骤切换后停止上一请求、清空结果、释放旧会话，连接绑定摄像头；新视频播放就绪后才截帧。
迟到的连接、截帧、识别结果通过请求序号与流代次丢弃。摄像头不可用时提示失败，禁止自动降级到第一台。
无配置、待确认、缺基准图、无有效区域均不开始检测；不支持的区域类型仍不会被误判为通过。步骤仍需人工确认。

## 版本和部署

执行 SOP 数据库迁移 `SOP_MySQL/sop-module-v1/migrations/002_step_detection.sql`（依赖资源模块），再启动新版 Java 服务。
表 sop_step_detection 按 step_id 一对一保存，随步骤删除级联清理；移除基准图时先清空绑定再删除图片引用。
草稿复制时会将源附件 ID 映射到新附件 ID，并保留摄像头和确认状态；原发布版本不变。
开工作业已有 content_snapshot 自动包含 detection，新发布不改变运行中的快照。
旧版本无配置时现场明确提示；含检测区域的旧草稿发布前必须明确配置检测或显式关闭视觉检测。

验证覆盖：保存重载、图片浏览不改检测基准、发布前确认校验、跨步骤附件拒绝、基准图移除与清空绑定、复制版本附件重映射、实时摄像头不可用不回退、拍照替换失败保留旧图、切换步骤迟到结果丢弃。
